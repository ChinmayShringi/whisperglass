### Boot smoke test detail

The unit tests do not exercise the real Electron main process (`src/main/index.ts`,
`createOverlayWindow`), so a boot smoke test was performed:

- `npm run dev` was started as a background process.
- After waiting for electron-vite to build and launch Electron, the captured dev
  output showed:
  - `electron main process built successfully`
  - `electron preload scripts built successfully`
  - `dev server running for the electron renderer process at: http://localhost:5173/`
  - `starting electron app...`
- A process scan confirmed an Electron process tree for this app was running
  (the main `Electron .` process plus GPU process, renderer, and network service
  helpers, all using `--user-data-dir` and `--app-path` pointing at this project).
- No uncaught exception, no fatal error, and no failed-to-load message were present
  in the dev output.
- The dev process and its Electron child processes were terminated cleanly; a
  follow-up scan confirmed no app processes remained.

## Manual verification checklist

The following checks require a real macOS machine with a display and cannot be
verified by an automated agent. The project owner should perform each one and
tick it off:

- [ ] Run `npm run dev`. The overlay appears as a transparent, frameless window near the top center of the screen, showing the command bar, the eye toggle, and the two empty panels ("No transcript yet", "No answer yet").
- [ ] Press Cmd+\ : the overlay hides. Press again: it reappears.
- [ ] Press Cmd+Shift+\ (or click the eye toggle): the eye toggle label flips between "Invisible: on" and "Invisible: off".
- [ ] With invisibility ON, start a macOS screen recording (Cmd+Shift+5). The overlay must NOT appear in the recording. With invisibility OFF, it must appear. This is the core content-protection check.
- [ ] Type a question in the command bar and press Cmd+Return: the input clears and the typed question appears as the active question line.
