## Real Codex CLI check

The app spawns `codex exec` via `buildCodexArgs` (`src/main/codex/codex-args.ts`).
To confirm the real CLI accepts the app's argument pattern and produces a parseable
stream, the exact command was reproduced directly:

```
mkdir -p /tmp/cc-phase2-verify
codex exec --json --ephemeral --skip-git-repo-check -s read-only \
  -C /tmp/cc-phase2-verify -o /tmp/cc-phase2-verify/out.txt \
  -c 'model_reasoning_effort="low"' "Reply with exactly the word: pong"
```

Environment: `codex` is installed at `/opt/homebrew/bin/codex` (codex-cli 0.125.0)
and the local session is authenticated.

Result (PASS):

- The command exited with code 0.
- Stdout was JSONL: 4 lines, one of which was an `item.completed` event carrying an
  `agent_message` item with `text` equal to `pong`:
  `{"type":"item.completed","item":{"id":"item_0","type":"agent_message","text":"pong"}}`
- The output file `/tmp/cc-phase2-verify/out.txt` was written and contained the
  answer text `pong`.
- Stderr contained two unrelated background warnings (a `codex_models_manager`
  model-refresh timeout and an `rmcp` MCP transport channel close for a local MCP
  endpoint not used by this run). Neither affected the exit code or the parseable
  JSONL stream, so the run is a clean PASS.
- The temp directory `/tmp/cc-phase2-verify` was removed afterward.

This confirms the real `codex exec` CLI accepts the app's flag pattern and emits a
JSONL stream the runner can parse, and writes the answer to the `-o` output file.
