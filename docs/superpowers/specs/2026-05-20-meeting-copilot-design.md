# Design Spec: Local AI Meeting-Copilot Overlay (macOS)

- **Date:** 2026-05-20
- **Status:** Approved (design)
- **Project:** Whisperglass

## 1. Summary

A macOS-only, local-first desktop app that delivers live meeting insights:
an always-on-top overlay that listens to a meeting, transcribes the
audio on-device, and streams concise AI answers into a small black-and-white
overlay UI.

The defining constraint: **no OpenAI API key lives in the app.** All AI
reasoning runs through the locally installed and already-authenticated `codex`
CLI (Codex CLI 0.125.0, confirmed installed at `/opt/homebrew/bin/codex`). This
mirrors how the OpenClaw harness drives Codex as an external agent process.

## 2. Decisions made during brainstorming

| Question | Decision | Reason |
|---|---|---|
| Target platform | macOS only | Cleanest capture and capture-exclusion APIs; user choice |
| AI provider | OpenAI Codex CLI, not the API | User: "local only, instead of API key use codex cli" |
| Architecture | Approach B-lite | Electron loopback system audio is Windows-only (Electron docs), so macOS needs a native capture path |
| Transcription | Local `whisper.cpp` | Codex cannot transcribe audio, and no API key is allowed, so speech-to-text must run on-device |
| Invisibility | Included as opt-in toggle, default OFF | Core to the request; ships as an opt-in feature, a common meeting-assistant pattern |

## 3. Goals

- Deliver live meeting insights: listen, transcribe, answer, all
  in a discreet overlay.
- Run AI through the `codex` CLI with zero API-key handling in the app.
- Run transcription fully on-device.
- macOS overlay that can be toggled invisible to screen-sharing software.

## 4. Non-goals (out of scope for v1)

Accounts, login, billing, calendar sync, pre-call briefs, post-call meeting
notes, enterprise features (knowledge base, CRM/ATS, directory sync), Windows
support, and code signing / notarization.

## 5. Success criteria

The build is done when all of the following are observed by running the real
app:

1. The overlay launches as a transparent, always-on-top, frameless window.
2. With invisibility ON, the overlay does not appear in a macOS screen
   recording or a Zoom/Meet/Teams screen share. With it OFF, it does appear.
3. Typing a question and pressing the submit hotkey streams a relevant answer
   into the overlay, generated by `codex exec`.
4. Speaking into the microphone produces live transcript text on-device, with
   no network call for transcription.
5. Audio from another macOS app (a call, a video) is captured by the sidecar
   and transcribed.
6. Default Actions ("What should I say next", "Fact check", etc.) produce
   answers that use the rolling transcript and an optional screenshot.
7. The app stores and requires no OpenAI API key; AI works purely via the
   user's existing `codex login`.
8. Logic modules reach 80%+ unit test coverage.

## 6. Architecture overview

The app is built from several cooperating processes, each with a single
responsibility and a defined interface: an Electron app (a main process and a
renderer process) plus three helper processes (the capture sidecar, the Codex
runner, and the Whisper transcriber). The Codex runner is transient, spawned
once per query; the others are long-lived.

| Component | Runtime | Responsibility |
|---|---|---|
| Electron main | Node.js | App lifecycle, windows, global hotkeys, orchestration, spawns and supervises children |
| Renderer | Chromium | Black-and-white UI: command bar, transcript panel, answer panel |
| Capture sidecar | Swift binary | System audio (ScreenCaptureKit), microphone, on-demand screenshots |
| Codex runner | `codex` subprocess | One AI request per query |
| Whisper transcriber | `whisper.cpp` subprocess | Audio chunks to text, on-device |

Rationale for the process split:

- The capture sidecar is a standalone Swift binary, not a Node native addon, so
  the native surface stays tiny, a crash restarts in isolation, and the macOS
  privacy (TCC) permission attaches to one helper.
- Codex and Whisper have opposite shapes: Whisper is a long-lived stream you
  feed continuously; Codex is a short-lived request spawned per question.
  Separate runners keep each one simple and independently testable.

## 7. Data flow

```
  Swift sidecar
    +-- system audio (ScreenCaptureKit SCStream) --+
    +-- microphone (AVAudioEngine) ----------------+--> PCM frames
    +-- screenshot on demand                       |
                                                   v
                                              whisper.cpp
                                                   |
                                                   v
                                       rolling transcript buffer
                                          |                  |
                            renderer transcript panel        |
                                                              v
  user hotkey / Default Action button / Tab --> prompt-builder
       (system prompt + rolling transcript + question + optional screenshot)
                                                              |
                                                              v
                       codex exec --json [--image shot.png] ...
                                                              |
                                                   JSONL event stream
                                                              v
                              renderer answer panel (streamed progressively)
```

## 8. Component specs

### 8.1 Electron main

- Creates the overlay window: `transparent: true`, `frame: false`,
  `alwaysOnTop` at screen-saver level, `resizable: false`, positioned
  top-center as the command bar.
- Owns `setContentProtection(boolean)` for the invisibility toggle.
- Registers global hotkeys via `globalShortcut` (see section 12).
- Spawns and supervises the sidecar, the Codex runner, and the Whisper
  transcriber.
- Hosts the session orchestrator and the IPC handlers.

### 8.2 Renderer

- React + TypeScript, deliberately minimal black-and-white styling.
- Components: `CommandBar`, `DefaultActions`, `TranscriptPanel`, `AnswerPanel`,
  `EyeToggle`, `SetupBanner`.
- Communicates with main only through a `contextBridge` preload API. No Node
  access in the renderer.

### 8.3 Capture sidecar (Swift)

- A SwiftPM executable, arm64, bundled inside the app.
- `SystemAudioCapture`: ScreenCaptureKit `SCStream` with audio capture enabled.
  The `SCContentFilter` excludes the app's own overlay window so screenshots
  never contain the overlay.
- `MicrophoneCapture`: `AVAudioEngine` tap, resampled to 16 kHz mono.
- `ScreenCapture`: a single frame captured on request.
- `StdioProtocol`: newline-delimited JSON over stdio (see section 11).
- Supervised by the main process: on crash, restarted with backoff; the UI
  shows "audio paused" until it recovers.

### 8.4 Codex runner

Spawns, per query:

```
codex exec --json --ephemeral --skip-git-repo-check \
  -s read-only -a never -C <scratch-dir> \
  [-i <screenshot.png>] -o <last-message.txt> "<prompt>"
```

- `--json`: stdout becomes a JSONL event stream (`thread.started`,
  `turn.started`, `item.*`, `turn.completed`, `turn.failed`, `error`). The
  runner parses `item.*` agent-message events to stream the answer
  progressively into the overlay.
- `-o`: the clean final answer is written to a file and used as the source of
  truth once the turn completes.
- `--ephemeral`, `-s read-only`, `-a never`: no session files on disk, no file
  edits, no approval prompts. Codex answers; it does not act.
- `-C <scratch-dir>`: an empty scratch directory so Codex never sees unrelated
  files. `--skip-git-repo-check` because the scratch dir is not a repo.
- `-c model_reasoning_effort="low"`: reduce latency.
- `--search`: added only for the "Fact check" Default Action.
- `exec resume --last`: carries conversation context across one meeting
  session.
- `--output-schema`: used for Default Actions that benefit from a structured
  result.

The **prompt** is assembled by `prompt-builder` from: a fixed system
instruction (real-time meeting copilot, answer in seconds, be concise, plain
text), the rolling transcript, and the user's question or selected Default
Action.

### 8.5 Whisper transcriber

- Bundled `whisper.cpp` binary (`whisper-cli`), Metal-accelerated.
- Default model `ggml-base.en.bin` (~142 MB), with `small.en` as an
  accuracy option. Models are downloaded on first run with a progress UI, not
  committed to git.
- Input audio is 16 kHz mono 16-bit PCM.
- Rolling-window transcription: audio is buffered into overlapping windows
  (about 6 to 10 seconds), transcribed, and overlap is de-duplicated before
  segments are appended to the transcript buffer.
- Segments carry a speaker hint: microphone audio is "you", system audio is
  "them".

### 8.6 Session orchestrator

- Start and stop a session (the overlay shows insights only during a session,
  using a session-scoped insight model).
- Wires audio to transcription to the rolling buffer.
- Runs `dynamic-insights`: detects questions and salient keywords in incoming
  transcript segments and surfaces them below the command bar.

## 9. Codex integration notes

- The app requires the user to have run `codex login` once. At startup the
  Codex runner verifies the binary (`codex --version`) and checks for
  authentication; if either is missing, a `SetupBanner` explains the fix.
- Latency: Codex is an agentic harness, so answers land in roughly 2 to 6
  seconds with low reasoning effort, slower than a tuned hosted-inference
  service. Token-by-token streaming into the overlay hides most of the wait.
  This is the single biggest trade-off of using the CLI instead of an API.
- The `codex app-server` JSON-RPC integration (the full OpenClaw pattern) is a
  later optimization, not part of v1. The v1 runner uses `codex exec` per
  query, which is simpler to build and debug.

## 10. Transcription notes

- Transcription runs entirely on-device; it makes no network calls. This
  satisfies the "local only, no API key" constraint.
- Microphone transcription is built and verified first (Phase 3) because the
  renderer can capture the mic via `getUserMedia` without the sidecar. This
  `getUserMedia` mic path is a stopgap whose only purpose is to validate the
  Whisper pipeline early.
- System audio transcription arrives with the sidecar (Phase 4). At that point
  the sidecar also takes over microphone capture, so all audio flows through a
  single path and the Phase 3 stopgap is removed.

## 11. Sidecar protocol

Newline-delimited JSON over stdio. Audio frames carry base64-encoded PCM
(about 43 KB/s at 16 kHz mono, trivial over a pipe and easy to debug).

Main to sidecar:

```
{"type":"start","capture":["systemAudio","mic"]}
{"type":"screenshot"}
{"type":"stop"}
{"type":"shutdown"}
```

Sidecar to main:

```
{"type":"audio","source":"system|mic","seq":N,"sampleRate":16000,"pcm":"<base64>"}
{"type":"screenshot","format":"png","data":"<base64>"}
{"type":"status","state":"capturing|stopped|error","detail":"..."}
{"type":"permission","kind":"screen|mic","granted":true|false}
```

## 12. Features (live meeting insights)

- Command bar, top-center, frameless, black-and-white.
- Default Actions: "What should I say next", "Follow-up questions",
  "Fact check", "Recap", "Coding help" (Smart Mode).
- Dynamic insights: questions and keywords detected from the transcript,
  shown below the command bar.
- Live transcript panel with speaker hints.
- Sessions: explicit start and stop.
- Invisibility: opt-in toggle (Eye icon plus hotkey), `setContentProtection`,
  default OFF.

## 13. Hotkeys

| Shortcut | Action |
|---|---|
| `Cmd+\` | Show / hide overlay |
| `Cmd+Enter` | Submit custom question |
| `Tab` | Answer first dynamic insight |
| `Cmd+Shift+Enter` | Stealth answer (answer while invisible) |
| `Cmd+Shift+\` | Toggle invisibility |
| `Cmd+Shift+M` | Toggle click-through |
| `Cmd+Arrows` | Move overlay |

## 14. Error handling

| Failure | Handling |
|---|---|
| Codex missing or not logged in | Detected at startup; `SetupBanner` with fix instructions |
| Screen Recording or Microphone permission denied | Detected; banner deep-links to System Settings |
| Sidecar crash | Supervisor restarts with backoff; UI shows "audio paused" |
| Whisper model missing | Downloaded on first run with a progress UI |
| Codex query error or timeout | Shown in the answer panel with a retry button |
| Offline | Codex needs network; surfaced clearly in the answer panel |

All errors are surfaced in the UI; none are swallowed silently.

## 15. Project structure

```
src/main/        windows/ hotkeys/ codex/ transcription/ sidecar/
                 session/ permissions/ ipc/ config/
src/preload/     contextBridge API
src/renderer/    React: components/ hooks/ styles/

                 ScreenCapture, StdioProtocol
```

Files stay small (200 to 400 lines typical), organized by feature.

## 16. Tech stack

- Electron + TypeScript, scaffolded with `electron-vite`.
- React + TypeScript for the renderer.
- Swift package (SwiftPM, arm64) for the capture sidecar.
- `whisper.cpp` bundled binary for transcription.
- `codex` CLI 0.125.0 (already installed) for AI.
- Packaged with `electron-builder`, unsigned for local use.
- Vitest for TypeScript tests, XCTest for Swift tests.

## 17. Testing strategy

- **Unit (Vitest):** prompt-builder, Codex JSONL parser, transcript buffer,
  sidecar protocol codec, hotkey map, dynamic-insight detector.
- **Integration:** Codex runner against a mock `codex` binary; Whisper runner
  against a fixture WAV; sidecar protocol round-trip.
- **Swift (XCTest):** protocol encoding/decoding, capture lifecycle.
- **End-to-end / verification:** run the real app, drive a real meeting,
  observe transcript and answers.
- Target: 80%+ unit coverage on logic modules.

## 18. Build phases

Each phase ends with a verifiable acceptance check.

### Phase 1: Electron overlay shell
Transparent always-on-top frameless window, black-and-white UI, global
hotkeys, manual text input field, invisibility toggle.
**Accept when:** the overlay appears, hotkeys show/hide it, and a screen
recording confirms `setContentProtection` hides it when invisibility is ON.

### Phase 2: Codex runner
Spawn `codex exec`, build the prompt, parse the JSONL stream, render the
answer progressively in the answer panel.
**Accept when:** typing a question and submitting streams a real Codex answer
into the overlay.

### Phase 3: Local transcription
Bundle `whisper.cpp`, transcribe microphone audio, maintain the rolling
transcript buffer and panel.
**Accept when:** speaking produces live transcript text with no network call.

### Phase 4: Swift capture sidecar
System audio capture and on-demand screenshots, streamed to Electron over
stdio; supervised with restart.
**Accept when:** audio from another app is captured and transcribed, and a
screenshot can be attached to a Codex query.

### Phase 5: Context intelligence
Rolling transcript summary, screenshot context, Default Actions, dynamic
insights.
**Accept when:** a full meeting flow works: listen, detect a question, answer
it using transcript and screen context.

## 19. Known risks and honest caveats

- **Codex latency:** answers take roughly 2 to 6 seconds; this is slower
  than a tuned hosted-inference service. Mitigated by streaming and low reasoning effort.
- **Invisibility scope:** `setContentProtection` hides the window from software
  screen capture only. It does not hide it from a phone camera pointed at the
  screen or from a hardware capture card.
- **macOS permissions for the helper:** TCC may require the sidecar binary to
  live inside a properly structured `.app` bundle for the Screen Recording
  permission to behave; this is validated during Phase 4 verification.
- **Codex is coding-tuned:** general-conversation quality depends on prompt
  steering in the system instruction.
- **Whisper accuracy vs speed:** the chosen model size trades accuracy against
  latency; `base.en` is the default, `small.en` the accuracy option.
