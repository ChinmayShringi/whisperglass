# Customcluely Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement each phase plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a macOS-only, local-first Cluely "Live Insights" clone: an always-on-top overlay that transcribes meetings on-device and streams AI answers via the `codex` CLI.

**Architecture:** An Electron app (main + renderer) provides the overlay UI and orchestration. A Swift capture sidecar provides macOS system audio and screenshots. Bundled `whisper.cpp` provides on-device transcription. The `codex` CLI is the AI brain. No OpenAI API key lives in the app.

**Tech Stack:** Electron, TypeScript, electron-vite, React, Swift (SwiftPM), whisper.cpp, codex CLI 0.125.0, Vitest, XCTest.

**Spec:** `docs/superpowers/specs/2026-05-20-cluely-clone-design.md`

---

## Execution model: 3 agents per task

Every task in every phase plan is executed by a 3-agent pipeline. The orchestrator (Claude) never implements directly; it dispatches and reviews.

1. **Implementer agent** - reads the task, writes the failing test, implements the minimal code to pass, runs the test.
2. **Auditor agent** - independently re-derives test cases from the task and the spec, runs them against the implementer's output, and audits requirement coverage (did the code do what the task and spec actually asked, not just what the implementer's own tests checked). Reports gaps.
3. **Documenter agent** - updates docs, writes the commit, commits the work, and updates auto-memory if anything durable was learned.

The orchestrator dispatches Implementer, reviews, then dispatches Auditor; if the Auditor finds gaps the orchestrator sends them back to a fresh Implementer; once clean, the orchestrator dispatches Documenter. Independent tasks within a phase are dispatched in parallel; phases run in dependency order.

## Why phases 2-5 are detailed just-in-time

Each phase plan is written immediately before that phase executes, so it can reference the real interfaces and file layout produced by the prior phase. This avoids speculative plans that drift from reality. The roadmap above is the contract; the per-phase plans are the detail.
